CardBook V3.1 help & admin setup

One-time private backend setup

  1. Open the supplied existing Google Sheet using the admin’s Google account. Open Extensions → Apps Script.
  2. Paste the supplied V3.1 Apps Script. Set BOOTSTRAP_ADMIN_PASSWORD to a unique password of at least 12 characters. Do not use a shared or existing Google password. The supplied existing Google Sheet ID and Drive folder ID are already hardcoded. Do not create another spreadsheet or photo folder. After bootstrap, clear the bootstrap password from the code before deploying.
  3. Choose bootstrapAdmin in the function list and click Run once. Authorise Sheets and Drive. This creates the first admin.
  4. Click Deploy → New deployment → Web app. Set Execute as: Me and Who has access: Anyone.
  5. Copy the /exec URL into the sign-in page. To fix the connection for every user, instead paste it into HARDCODED_APPS_SCRIPT_URL near the top of the main script in index.html; The required Sheet and Drive IDs are already fixed beside it. Hardcoded values override saved device settings. Sign in as admin, open Users & access, and create each user with a separate password.
  6. After any backend edit: Deploy → Manage deployments → pencil → Version: New version → Deploy.
Ordinary users must not be given access to the underlying Google Sheet or the “CardBook Private Receipts” Drive folder. The backend filters records by owner and checks every session.

Private contacts and scanner

  1. Choose or photograph one or more visiting cards. OpenCV improves framing and contrast; Tesseract reads the text in your browser.
  2. Verify every field before saving. Contacts are visible only to their owner and admins.
  3. Login immediately restores the user’s cached workspace, then pulls all seven cloud collections and uploads pending edits. Local browser data alone is not cross-device.

Things to do

Add professional or personal tasks with start/final dates, project links and completion notes. The month calendar draws each task across its full date range.

Wallet, entrusted money and payments

  1. Amount received: enter the amount, date, source type and salary/account/source details.
  2. Give money: choose the person, amount and date. Attach the bank/e-PayOrder proof and verify OCR suggestions.
  3. Add person’s expense: use the same person’s name and upload their WhatsApp, Google Pay or PhonePe screenshot. Multiple payment cards appear as separate editable rows; untick false detections and save selected rows.
  4. The ledger shows given, spent and left for each person. Your own balance subtracts advances once and never subtracts their expenses again.
  5. Receipts and advance proofs upload only during sync and remain private in the admin’s Drive. Viewing requires the owner’s session or an admin session.

One combined Excel workbook

Use Workbook .xls to export Summary, Contacts, To-dos, Wallet, Expenses, Projects, Goals and encrypted Vault worksheets together in one legacy Excel-compatible file. Receipt images remain private and are represented by their file name/ID, not embedded in XLS.

GitHub Pages

Upload index.html to the repository root, then Settings → Pages → Deploy from a branch → main → /(root). The Apps Script backend remains separate.

Security notes

  • Passwords are salted and hashed; sessions expire after six hours. Never reuse your Google password.
  • LinkedIn uses Connections.csv and research links only. CardBook never asks for LinkedIn or Google Pay credentials.
  • Use HTTPS GitHub Pages, keep admin credentials private, and deactivate departed users.
